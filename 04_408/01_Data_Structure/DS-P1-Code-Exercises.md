## 复杂度：先分清轮数与每轮代价

### 我的推导链

手稿从**倍增**和**折半**两个方向追问同一件事：规模按固定倍数变化，需要多少轮才到边界？

```c
size_t halving_rounds(size_t n) {
    size_t rounds = 0;
    while (n > 1) {
        n /= 2;            // 每轮规模折半
        ++rounds;
    }
    return rounds;          // 轮数为 O(log n)，不代表整段程序的总耗时
}
```

若用 $k$ 表示轮数，倍增得到 $2^k\approx n$，折半得到 $n/2^k\approx1$；两条式子都指向 $k\approx\log_2 n$。原始循环的严格停止条件有涂改，所以这里讨论的是数量级，不替某道题确定取整或不等号。

### 从轮数走到总工作量

手稿还把多个 $n$ 相加，并列出 $1+2+\cdots$、$1+2+4+\cdots$ 等不同求和过程。这提示我把分析拆成两步：

1. 先找循环或递归有多少层。
2. 再看每层究竟做常数、$n$ 次，还是随层数变化的工作，然后求和。

例如，**只有在每层确实做 $n$ 量级工作且共有 $\log n$ 层时**，总工作量才是 $n\log n$ 量级。不能看见折半就把整段程序直接写成 $O(\log n)$。

另一组演算从 $k^2<n$ 推到 $k<\sqrt n$，是在用循环变量的增长关系寻找终止轮次；它与倍增折半不是同一道式子，不能混成一个复杂度答案。

> [!question] 待确认
> 几个被划改的求和式、层级树和 $2^h-1$ 旁缺少完整原题条件。目前只能保留分析方法，不能给它们统一的最终复杂度。

**一句话记忆：** 先数层，再算层内工作；不同增长方式分别列式。

## 双链表与表达式：把“过程”还原为状态变化

### 双链表插入：先保护旧连接

手稿以 A、B 之间插入 C 为例，反复调整 `next` 和 `prior`。可复述的目标状态是 `A ⇄ C ⇄ B`：先让 C 接上原后继 B，再让 B 回指 C，最后让 A 与 C 互指。这样理解比死记四行赋值更能检查是否漏掉一条反向连接。

```c
typedef struct DNode {
    int data;
    struct DNode *prior, *next;
} DNode;

void insert_between(DNode *a, DNode *b, DNode *c) {
    // 前置条件：a、b、c 非空，且 a->next == b、b->prior == a。
    c->next = b;             // 先保存原后继，形成 c -> b
    b->prior = c;            // 再形成 b -> c
    a->next = c;             // 最后把 a 与 c 双向连接
    c->prior = a;
}
```

这是图中 B 确实存在时的手写思路。空表、尾结点和指针有效性没有完整题设，不能当作通用、已验证的 C 函数。

### 表达式转换与表达式树

中缀到后缀的演算反复改动运算符、括号和栈内顺序。可提炼的检查问题是：**当前运算符该入栈、弹出，还是等待右括号？** 不能凭涂改后的字符拼出唯一原题和唯一后缀式。

表达式树的多次画法则把操作数放在叶子、运算符放在内部结点。复盘时应先确定子表达式如何结合，再确定树的父子关系；具体原式和最终有效树形仍为 `[?]`。

## 树的遍历：访问顺序由规则和树形共同决定

### 层序遍历为何用队列

手写流程先把根入队，之后反复出队、访问，再把存在的左孩子和右孩子入队。队列让较早进入的同层结点先处理，下一层结点排在其后。

```c
// Queue 是课程中已有的结点指针队列；此处只展示遍历控制流程。
void level_order(TreeNode *root, Queue *q) {
    if (root == NULL) return;
    enqueue(q, root);
    while (!queue_empty(q)) {
        TreeNode *p = dequeue(q);
        visit(p);             // 出队时访问；先入队的同层结点先处理
        if (p->lchild != NULL) enqueue(q, p->lchild);
        if (p->rchild != NULL) enqueue(q, p->rchild);
    }
}
```

树形图和结点连线有多版改动，因此手稿中的字母序列不能直接升格为唯一答案。遇到具体题时，先固定树的最终结构及左右孩子，再手推队列状态。

## 中序线索二叉树：围绕 `pre` 与当前结点维护前驱和后继

### 我在维护的关系

这组代码反复使用 `pre`、当前结点（草稿中也写作 `q` 或 `cur`）、左右指针和标志位。可辨的主线是：**按中序走到当前结点时，`pre` 保存刚访问过的结点**。

进入递归前令 `pre = NULL`，递归参数 `q` 指向当前结点；处理两者之间的空指针之后才更新 `pre = q`。对应的 C 参考片段见下方。

- 当前结点左指针为空时，可以把它标为指向中序前驱的线索。
- `pre` 非空且右指针为空时，可以把 `pre` 的右指针标为指向当前结点的线索。
- 每次处理完当前结点再更新 `pre`，否则下一次访问时会失去“前一个结点”的含义。

### 找首末结点与找相邻结点

`FirstNode`、`LastNode`、`NextNode`、`FrontNode` 的多版草稿都在区分两种指针：**真实孩子**与**线索**。理解性骨架是沿真实左孩子找中序首结点、沿真实右孩子找末结点；找后继或前驱时，先看标志位决定能否直接沿线索走，否则进入相应子树再找首/末结点。

#### 可复盘的中序线索化流程（C 参考片段）

```c
#include <stddef.h>

typedef struct ThreadNode {
    struct ThreadNode *lchild, *rchild;
    int ltag, rtag;          // 0：孩子；1：线索
} ThreadNode;

// 调用前：所有 ltag、rtag 均为 0。
void in_thread(ThreadNode *q, ThreadNode **pre) {
    if (q == NULL) return;

    if (q->ltag == 0) in_thread(q->lchild, pre);
    if (q->lchild == NULL) {
        q->lchild = *pre;
        q->ltag = 1;
    }
    if (*pre != NULL && (*pre)->rchild == NULL) {
        (*pre)->rchild = q;
        (*pre)->rtag = 1;
    }
    *pre = q;

    // rtag 为 1 时，右指针是线索，不能当作右子树递归。
    if (q->rtag == 0) in_thread(q->rchild, pre);
}

void create_in_thread(ThreadNode *root) {
    ThreadNode *pre = NULL;
    in_thread(root, &pre);
}
```

这里的关键控制条件是：**递归进入的是原本的真实孩子**。处理当前结点以后若右指针被改成线索，必须由标志位区分，不能沿线索再次递归。首结点无前驱、末结点无后继时可保留空线索；是否使用头结点须由具体题目决定。

> [!danger] 可能混淆
> 标志位若表明“线索”，就不能继续把该指针当成真实子树递归。手稿在这类分支以及 `pre == NULL` 的边界上多次改动；这提示需要复盘，并不等于确认哪版代码正确。

> [!question] 待确认
> 首末结点和前驱、后继函数的完整条件分支、返回值及空树边界未验证。上面仅是线索化关键函数的参考片段。

**一句话记忆：** 当前左空可连前驱，前驱右空可连当前；走树还是走线索先看标志位。

## 图的存储与遍历：先弄清结构，再手推访问

下列图算法共用抽象邻接接口。具体图、队列的存储代码没有从手稿中可靠还原，因此这里保留接口声明，算法主体只展示状态与控制流。

```c
#include <stdbool.h>
#include <limits.h>
#define INF (INT_MAX / 4)

typedef struct Graph Graph;
typedef struct IntQueue IntQueue;

int first_neighbor(const Graph *g, int v);          // 无邻居时返回 -1
int next_neighbor(const Graph *g, int v, int w);    // 无下一邻居时返回 -1
int edge_weight(const Graph *g, int u, int v);      // 仅用于非负权图
bool int_queue_empty(const IntQueue *q);
void enqueue_int(IntQueue *q, int v);
int dequeue_int(IntQueue *q);
void visit_vertex(int v);
```

### 存储结构决定怎样找邻接点

手稿把图画成矩阵、链式邻接结点和带边链接的结构，又尝试写 `Adjacent(G,x,y)`、`Neighbors(G,x)`。这几页研究的共同问题是：**给定表示法，怎样判断两点相邻或列出某点的邻居？**

| 表示线索 | 手稿中可辨的查找入口 | 待核对处 |
|---|---|---|
| 邻接矩阵 | 按两个顶点下标定位单元格 | 顶点编号与返回值约定 |
| 链式表示 | 从顶点的首邻接结点沿链接查找 | 边方向、链接字段与终止条件 |

并查集片段则是另一个问题：`Find` 沿 `parent` 找根；`Union` 先找两个根，再判断是否属于不同集合。初始化、合并方向和具体优化方式没有完整记录。

#### 从存储到操作的变量链

- 邻接矩阵：先定位顶点下标，再查询对应单元；列邻居时扫描整行。
- 邻接表：从首边指针沿 `next` 扫描；有向图须确认扫描的是出边。
- 十字链表：顶点分别关联出边链和入边链，按所问方向选链。
- 并查集：`Find` 沿 `parent` 到根；`Union` 仅连接不同根。

`Find` 草稿使用 `parent[n] >= 0` 作为“还未到根”的条件。此条件依赖“根以负值标记”的数组约定；换一种初始化就不能照抄。路径压缩与按秩合并未在本批代码中确认，不作为个人已写实现。

### BFS：队列、访问标记与邻接顺序

BFS 草稿反复出现三个状态：队列保存待扩展顶点，`visited` 防止重复入队，输出顺序记录访问过程。

图上的边与部分手推序列有改动；**邻接点顺序不明确时，不能宣称唯一 BFS 序列**。旧附录中的 DFS 框架尚未与这批原图建立来源对应，不把它当作本批个人手推结论。

#### BFS 代码流程检查

```c
// Graph 与 IntQueue 的接口由具体存储结构提供；邻接枚举顺序由题目规定。
void bfs(const Graph *g, int s, bool visited[], IntQueue *q) {
    visited[s] = true;
    visit_vertex(s);
    enqueue_int(q, s);

    while (!int_queue_empty(q)) {
        int v = dequeue_int(q);
        for (int w = first_neighbor(g, v); w != -1;
             w = next_neighbor(g, v, w)) {
            if (visited[w]) continue;
            visited[w] = true;  // 入队时标记，避免重复入队
            visit_vertex(w);
            enqueue_int(q, w);
        }
    }
}
```

**入队时就标记**可防止同一顶点被多个前驱重复入队。单次从 `s` 开始只覆盖其可达部分；若题目要求遍历整个非连通图，外层还须遍历未访问顶点并再次启动 BFS。邻接矩阵枚举邻居通常逐行扫描；邻接表则沿边链扫描，顺序由存储/题设决定。

## 最短路径：距离状态与路径状态要一起维护

### 无权图：BFS 的层次就是边数

无权最短路草稿在遍历之外增加 `len` 和 `path`：起点 `len=0`，首次发现邻居时写入 `len[w]=len[v]+1`，并把 `path[w]` 记为发现它的顶点。队列确保先处理较少边数的层。

| 状态 | 手稿中的用途 |
|---|---|
| `visited` | 避免重复处理同一顶点 |
| `len` | 已发现路径的边数 |
| `path` | 回溯该路径的前驱 |

数值填表有覆盖和改写，不能据此宣布具体顶点的最短距离已经核对。

#### 无权最短路的状态更新（C 参考片段）

```c
// len == -1 表示尚未到达；首次发现时写入最短边数与前驱。
void bfs_shortest(const Graph *g, int s, int n,
                  int len[], int path[], IntQueue *q) {
    for (int i = 0; i < n; ++i) {
        len[i] = -1;
        path[i] = -1;
    }
    len[s] = 0;
    enqueue_int(q, s);

    while (!int_queue_empty(q)) {
        int v = dequeue_int(q);
        for (int w = first_neighbor(g, v); w != -1;
             w = next_neighbor(g, v, w)) {
            if (len[w] != -1) continue;
            len[w] = len[v] + 1;
            path[w] = v;
            enqueue_int(q, w);
        }
    }
}
```

首次发现即锁定无权图的最少边数；未到达顶点仍为 `∞/-1`。`path` 记录**前驱**，从终点沿前驱回溯到起点后要反转，才能得到正向路径。

### Dijkstra：`final`、`dist`、`path` 与“选点—松弛”

带权图手推和代码草稿围绕三个数组展开：

| 状态 | 复盘时要问 |
|---|---|
| `final[i]` | 顶点 $i$ 的距离是否已被确定？ |
| `dist[i]` | 当前记录的候选距离是多少？ |
| `path[i]` | 该候选路径从哪个前驱到达？ |

每一轮先从未确定顶点中找 `dist` 最小者，再用它检查邻接点能否得到更短的候选距离；发生更新时，距离和前驱要一起检查。这解释了手稿为何同时维护三个数组，而不只写最终距离。原图中的权值、循环边界和路径表格有涂改，**不输出本题最终路径**；下方是按通用流程重建的参考片段，并非原图完整代码。

#### Dijkstra 的一轮与已证实错误

```c
// 前提：0 <= weight(u,w) < INF；无边由邻接接口跳过。
void dijkstra(const Graph *g, int s, int n,
              int dist[], int path[], bool final[]) {
    for (int i = 0; i < n; ++i) {
        dist[i] = INF;
        path[i] = -1;
        final[i] = false;
    }
    dist[s] = 0;

    for (int step = 0; step < n; ++step) {
        int u = -1;
        for (int v = 0; v < n; ++v) {
            if (!final[v] && (u == -1 || dist[v] < dist[u])) u = v;
        }
        if (u == -1 || dist[u] == INF) break;
        final[u] = true;  // 先选出 u，再确定其最短距离

        for (int w = first_neighbor(g, u); w != -1;
             w = next_neighbor(g, u, w)) {
            int weight = edge_weight(g, u, w);
            if (final[w] || dist[u] > INF - weight) continue;
            if (dist[u] + weight < dist[w]) {
                dist[w] = dist[u] + weight;
                path[w] = u;  // 距离和前驱同步更新
            }
        }
    }
}
```

> [!danger] 我的错误（已证实）
> **草稿在选出最小候选顶点之前就写 `final[u]=true`，该行被明确划错；此时 `u` 尚未赋值，不能作为数组下标。** 先完成“从未确定顶点中选 `u`”，再置 `final[u]`，然后松弛出边。复盘时把这三步分开写。

Dijkstra 的上述流程以**边权非负**为前提；只靠 `dist` 的数值而未同步更新 `path`，最后无法按本表重建路线。数组实现的逐轮选点与边松弛可在邻接矩阵下作 $O(|V|^2)$ 的上界分析；具体实现仍需结合图的存储方式。

### Floyd：`A` 更新距离，`Path` 留下路径线索

Floyd 草稿从中转点 $k$ 出发，逐对比较 $i,j$：

$$
A[i][j]>A[i][k]+A[k][j]
\quad\Longrightarrow\quad
A[i][j]\leftarrow A[i][k]+A[k][j].
$$

另一组递归树把“从起点到终点”沿记录的中转点拆成两个子问题，再继续拆到不需要中转为止。这说明 `Path` 的用途在于**重建路线**，不能只维护距离矩阵而丢掉路径状态。

#### Floyd 的更新与中转点定义（C 参考片段）

```c
// 调用前：A 为邻接矩阵，对角线为 0，无边为 INF；Path 全部为 -1。
// 有限距离需落在 (-INF, INF) 内；这里不处理负权环。
void floyd(int n, int A[n][n], int Path[n][n]) {
    for (int k = 0; k < n; ++k) {
        for (int i = 0; i < n; ++i) {
            for (int j = 0; j < n; ++j) {
                if (A[i][k] == INF || A[k][j] == INF) continue;
                long long candidate = (long long)A[i][k] + A[k][j];
                if (candidate <= -INF || candidate >= INF) continue;
                if (candidate < A[i][j]) {
                    A[i][j] = (int)candidate;
                    Path[i][j] = k;  // 记录当前最短路使用的中转点
                }
            }
        }
    }
}
```

这里明确选用“`Path[i][j]` 存中转点”的约定。若 `Path[i][j]=k`，复原路线时先展开 `(i,k)` 再展开 `(k,j)`，公共端点 `k` 只输出一次；若为 `-1`，应结合原图邻接矩阵判断是直达边、同一点还是不可达。手稿中另有 `path` 赋值与递归打印的涂改，不能直接与这套约定混用。

**一句话记忆：** 无权图用 BFS 记层数和前驱；Dijkstra 逐轮确定候选距离；Floyd 尝试每个中转点，并另存路径线索。

### 既有1. 复杂度与递归推导

这部分草稿包含：

- $2^x=n \Rightarrow x=\log_2 n$
- 等比数列求和
- 递归层数与问题规模变化
- 类似 $n,n/2,n/4,\ldots$ 的层级推导

#### 可确认的通用推导

若问题规模每次缩小为原来的 $1/2$：

$$
n,\frac n2,\frac n{2^2},\ldots,\frac n{2^k}
$$

当：

$$
\frac n{2^k}=1
$$

则：

$$
k=\log_2n
$$

因此“递归/循环执行多少层”常转化为对数级推导。

#### Floyd 推荐写法

核心更新：

$$
A^{(k)}[i][j]
=
\min
\left(
A^{(k-1)}[i][j],
A^{(k-1)}[i][k]+A^{(k-1)}[k][j]
\right)
$$

草稿以后建议逐轮保存 $A^{(-1)},A^{(0)},A^{(1)},\ldots$，避免只写最终答案。
