# 笔记整理 Schema

本文件是笔记**微观内容结构**的唯一契约。跨学科的证据、命名、双链与原图规则仍以 [CLAUDE.md](../CLAUDE.md) 为准；新一批手写图的摄入步骤见 [INGEST-SOP.md](INGEST-SOP.md)。分类约束的是一条知识、一段推导或一道题，不要求每篇文档反复填同一套空标题。

## 适用范围与分类

| 内容类型 | 408 | 数学（二） | 英语（二） | 政治考纲 | 政治 `00_Readings/` |
|---|---|---|---|---|---|
| 概念 / 结论 | 使用 | 使用 | 使用；词汇、句法分别细化 | 使用 | 需要时使用 |
| 推导 / 证明 | 使用 | 使用 | — | — | — |
| 例题 / 习题 | 使用 | 使用 | 使用；含训练模板子型 | 使用 | 需要时使用 |
| 算法 / 代码 | 使用 | — | — | — | — |
| 错题 / 澄清 | 使用 | 使用 | 使用 | 使用 | 使用 |
| 读书观点 / 论证 | — | — | — | — | 使用 |
| 方法 / 策略 | — | **待启用** | — | — | — |

“—”表示该学科不套用该类型。数学的“方法 / 策略”只保留路由：单题解法先留在该题内；积累足够做题复盘后，由用户确认规律或明确要求提炼，才建立通用方法。Agent 不从少量题目自行总结成已验证套路。

当前数据结构和高数仍采用“知识主干 ↔ 学习总结”双文档。类型是文档内部的内容单位，不触发按类型拆文件；同主题先续写已有文档。英语按能力分支存放，政治读书总结与考纲笔记分轨。

## 所有类型共守的边界

1. 每个内容单位让读者看出：**问题或用途、核心内容、成立条件**；证据状态影响结论或归属时就地标明。通用来源放在 frontmatter，原图批次放清单；补充示例、疑点和不同来源在出现处标明，不为它们另设篇首免责声明。缺项先在聊天中提问；未澄清的细节不写入新笔记，不用空模板伪装完整。
2. 手稿可辨事实、Agent 的解释、教材或外部补充要能区分；未解决的细节先在聊天中提问，不写入新笔记。自拟的最小示例允许用于解释概念，但须标“补充示例”、核对计算与条件，不冒充用户原题或教材原题。
3. 正式术语保留。标题中出现的专业术语写作 `中文（English）`；同一篇正文首次出现时也标注一次，后文可只用中文。英文本身已是原文的英语词汇不重复附英文。没有可核实的通行英文名称时保留中文；无法核实的译名先在聊天中提问，不把直译伪称原名。
4. 英文名称写在 Markdown 文字中，不塞入 `$...$` 或 `$$...$$`。标题与双链的文件名互不改变；跨文档标题链接若因改标题失效，须同步修复。
5. 面向学过高中知识、正在学习高数的大学生：先解释新术语的含义，再给严谨表述。一个自然段只承担一个主要意思；普通代数变形无需逐行复述，关键跳步必须说清依据。避免把比喻当定理或用一串抽象名词代替解释。
6. 各类型统一**必需信息与证据标准**，不统一固定小标题或排版。短内容可合并成一段；表格、公式、文本图示、代码按内容选择。

## 概念 / 结论

**共同必需信息：** 它回答什么问题；准确的定义、关系或结论；对象、范围与前提；一个容易混淆的边界；能链接时链到对应推导或题目。只写定义或只堆公式不达标。

### 数学（二）

按以下阅读顺序组织，简单知识点可合并步骤：

1. 一两句白话说明概念要解决什么问题或区分什么现象。
2. 给出正式术语、严谨定义或公式。
3. 说明适用条件与易混反例；没有合适反例时写清边界即可，不为填模板生造。
4. 链接已有证明、题目或相关概念。

定义、定理和关键公式**首次出现**时，说明符号代表什么、成立条件是什么、式子实际告诉读者什么。连续计算只解释关键跳步。术语首次出现给一句白话释义；后文正常使用术语。

### 408

保留当前适合对比表、文本图示和 C 片段的组织方式。概念仍须交代用途、定义或状态关系、边界条件和常见混淆；算法过程放在“算法 / 代码”或“推导 / 证明”，不要把未经验证的实现升为正式结论。

### 英语（二）

- **词汇：** 先写现代核心义和词性，再给自然搭配、易混点及可核对的例句或语境来源。词源、词根仅作记忆线索，不代替现代词义；无出处的句子不标“真题”。
- **句法：** 保留原句，指出主干、修饰成分依附对象、对应译法与该分析的边界。不能从一条例句推出普遍规则；自拟改写须与原句分开。

### 政治考纲

概念与结论按知识点或知识点组写明教材 / 大纲**版本与出处**，并区分原文、转述与自己的理解。版本未确认时先在聊天中提问，未解决前不写成已核实考点。读书笔记不能替代考纲来源。

## 推导 / 证明

适用于数学证明和 408 中可核实的算法推理。必需信息是：**要证明什么 → 关键构造或状态为何这样选 → 严谨推导及关键跳步的理由 → 结论依赖哪些条件**。短证明可以合并段落，不强制四个小标题。

数学可先用一句白话说明突破口，再写完整数学链；符号及量词的作用要可追踪。408 要写清关键变量、不变量或状态变化，代码另按“算法 / 代码”归类。手稿缺前提时，先在聊天中提问；若仍不足，只记录可确认的局部推导。

## 例题 / 习题

必需信息是：**最小完整题设（条件、目标、所求量）→ 解题入口 → 关键步骤及理由 → 结果与检查 → 可复盘的易混点**。最小完整题设须足以在脱离原图后独立重做；不必机械抄录无关叙述。原题条件缺失时先在聊天中提问；若仍不足，只保留能核实的局部计算，不给唯一标准答案。

单题的解法留在该题下；数学的通用“方法 / 策略”尚未启用。已证实错误按下文处理，疑似错误不得伪装成复盘结论。

**英语训练模板子型：** 如语境阅读 Prompt 或写作练习框架，写明输入材料、训练任务、预期输出与核对方式。生成材料不是历年真题，也不能据此判定用户已掌握。

## 算法 / 代码（408）

交代算法目的、输入输出、关键变量或不变量、控制流程、边界条件；能推导时再写时间和空间复杂度。代码块只用 C 语法及 `//` 注释表达流程，不混入中文伪代码或箭头步骤。代码块外可用中文解释“为什么这样安排”。

区分“用户原代码”“依据已知流程重建的参考片段”“已验证的完整实现”。原题、接口或实现不完整时，只保留可靠片段；未解决的条件在聊天中提问，不补出看似可运行的答案。保留当前 408 笔记可读的变量链、状态变化与一句话记忆；这些是帮助复盘的写法，不是必须填满的固定栏位。

## 错题 / 澄清

**红笔订正 / 红笔补充：** 用户约定红笔字迹用于修改错误或补充内容。能辨认且能对应到题目时，直接在该题的错题或解题记录中追加标注，保留原步骤与红笔内容的先后关系。红笔改动了可辨的原步骤时写“红笔订正”；只增加条件、解释或结论时写“红笔补充”，不据此推定原解法有错。字迹或对应关系不清时先在聊天中提问，未澄清的细节不写入笔记，不替红笔补写原意。

**已证实错误：** 仅当红笔明确纠正的原步骤可辨、原图明确标错、用户明确指出，或凭完整题目和过程可核实时，才能写“**我的错误**”并加粗。记录原动作、错因、正确做法、下次检查点，并链接对应知识点或题目。

**可能混淆：** 说明容易混在一起的条件或步骤，不宣称用户犯过错。

**未解决信息：** 缺题设、字迹、教材版本、答案或推导前提时，先在聊天中问用户；未澄清的细节暂不写入新笔记，也不标“正确”或“已掌握”。旧笔记中的占位标记另开清理任务。

## 读书观点 / 论证（政治 `00_Readings/`）

保留**我的原话 / 原书依据 / 二次提炼 / 与考纲的关系**四个信息层。引文、转述和个人推论分别标明；考纲对照须使用考纲口径和相应来源，不能把《中国通史》或原典观点直接写成标准答案。未读章节不补提要，未解决的疑问留在聊天中。

- [ ] 数学证明交代构造理由与关键跳步；习题有足以重做的题设，缺失处明确标记。
- [ ] 专业术语按 `中文（English）` 标注；未核实译名不硬译，公式内没有英文说明。
- [ ] 原始事实、补充示例、已证实错误和可能混淆没有混写；未解决的细节未进入新笔记。

- [ ] 408 的 C 片段保持纯 C 语法与 `//` 注释；英语与政治按各自子型及来源边界检查。
- [ ] 采用双文档的主题互链；所有链接可达，笔记脱离原图仍能独立阅读。
